# Docker client example

A standalone .NET 10 client using the published `squirix` `0.1.0-preview.10` NuGet package.
No source project references or changes to the host certificate store are required.

Prerequisites: Docker Desktop with Linux containers and Docker Compose 2.17 or newer (`additional_contexts` support).
Run commands from the repository root:

```bash
docker compose -f docker/docker-compose.yml up -d --build
docker compose -f docker/docker-compose.yml -f docker/docker-compose.client.yml run --rm --build --no-deps client
```

Wait until all three nodes report `Server is ready` in `docker compose -f docker/docker-compose.yml logs` before running the client.
The client exits successfully after writing and reading a unique key, printing:

```text
Found=True; Value=hello from Docker
```

The client uses the Compose network names and port 5000, not the published host ports 5001–5003.
It creates a five-minute HS256 JWT with the public development key, issuer and audience from `docker-compose.yml`.
The client image extracts the HTTPS certificate from the node A image and trusts it inside the client container.
Normal TLS certificate and hostname validation remain enabled. No private keys are copied into the final client image.
The example assumes all three nodes use the shared HTTPS certificate generated by the Dockerfile.
Rebuild the client image after rebuilding the server images so its trusted certificate matches.

These credentials and certificates are for local evaluation only. The sample does not configure production authentication,
exercise failover, or verify persistence after restart. Do not reuse this trust setup or the development signing key in production.

Stop the cluster without deleting its data:

```bash
docker compose -f docker/docker-compose.yml down
```
