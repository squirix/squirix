# v0.1.0-preview.9

## Summary

Squirix 0.1.0-preview.9 adds opt-in automatic failover for RF>=3: when a group leader goes silent, the other members
elect a new one by majority vote, reads are confirmed by a quorum, and any node routes calls to the current leader.
Replica groups now repair themselves: a lagging follower catches up from the leader's log, and a follower behind the
compacted log or back on an empty disk gets a state transfer. Key ownership moves to XxHash64 and the journal, manifest,
snapshot and group-log formats changed, so upgrading means a full-cluster restart on empty data directories.

Still an early preview — not production-ready. API, wire format, and on-disk layouts may change during 0.x.

## Changes

- **Breaking (cluster):** key ownership hashes route keys and virtual nodes with XxHash64 instead of SHA-256, so almost
  every key changes owner; upgrade is a full-cluster restart on empty data directories
- **Breaking (storage):** new on-disk formats with no migration: journal format version 3 (every touch, persist and
  update journals the full resulting entry; the `TouchExpiration` and `RemoveExpiration` frames are gone), one
  two-slot `man-current` manifest instead of numbered `man-NNNNNN.bmqx` files, snapshot files named `snp-NNNNNN.bsqx`,
  and two-slot / two-generation replica group log, snapshot and metadata files; a data directory written by
  0.1.0-preview.8, RF=1 included, refuses to start and is left unchanged
- **Breaking (cluster):** minimum cluster package version is `0.1.0-preview.9`; the replication protocol changed and the
  failover switches are part of the topology fingerprint, so mixed versions fail readiness and RF>1 data directories
  activated by an earlier build refuse to start
- **Breaking (server hosting):** `MapSquirixServer` is replaced by `MapSquirixServerAsync`, which opens node storage
  (activated-topology check, journal startup repair, replica group logs) after `Build()`; storage failures now
  surface from `MapSquirixServerAsync` instead of `AddSquirixServerAsync`, and the application must be disposed
  when it throws
- **Breaking (server hosting):** `Configurator.ResolveValidatedDataDirectory` is removed in favor of
  `ResolveEffectiveDataDirectory`, which also resolves the default data directory; the public `JournalPlatformBackend`
  enum is removed; `SquirixServer.StartAsync` throws when a discovered settings file fails to load instead of falling
  back to defaults
- **Breaking (backpressure):** the `RejectThreshold` limit and the `hard_threshold` rejection reason are removed; load
  is shed by `MaxInFlight`, `MaxQueue` (`queue_full`) and `MaxQueueWait` (`queue_wait_timeout`), and a settings file
  with `RejectThreshold` or another unknown key fails to load
- **Breaking (security):** symmetric JWT mode requires `SQUIRIX_JWT_AUDIENCE`, and `SQUIRIX_JWT_SIGNING_KEY` must be
  base64 that decodes to at least 32 bytes (no raw-text keys); the Docker dev key is now its base64 form, with the
  same key bytes
- **Breaking (security):** an internode mTLS node certificate that lists extended key usages must allow both
  `serverAuth` and `clientAuth`, and chains are built without network downloads, so an intermediate must be in
  `SQUIRIX_CLUSTER_MTLS_CA_PATH` or the OS store
- **Breaking (persistence):** on Unix the node creates data files `0600` and directories `0700` and tightens its own
  entries at startup, so a process running as another user can no longer read them; a node refuses to start on a
  data directory another node holds (`node.lock`)
- **Breaking (memory):** `MaxEstimatedCacheBytes` bounds every entry the node holds, follower copies and recovered
  entries included, and the per-entry size estimate is recalibrated; raise a manually set value on hosts that hold
  several copies
- **Breaking (client):** the `CacheExpirationResult` comparison operators with `TimeSpan` take the result by `in`
  reference, so code compiled against preview.8 must be recompiled; an absolute expiration is judged on the client
  clock, and one that is not in the future throws `ArgumentOutOfRangeException`
- **Breaking (observability):** journal compaction is removed, together with the `compaction.*` section of
  `/health/ready/details` and `squirix_compaction_duration_seconds`; snapshots plus retention keep the journal at its
  tail; serializer metrics are recorded only on the client `Squirix` meter
- Automatic failover for RF>=3, opt-in with `AutomaticFailoverEnabled` and `QuorumReadsEnabled` (settings keys under
  `Squirix:Cluster`; both required together, `ReplicaCount` of at least 3, same value on every node, set on empty data
  directories): when a group leader goes silent, the other members elect a new leader by majority vote; off by default,
  where the owner of each key leads its group
- Quorum reads with failover on: the leader confirms a majority before it answers a read; refused reads fail with
  `Unavailable` (`read_quorum_unconfirmed`, `read_index_unapplied`) and never return a possibly stale value
- A leader that cannot commit an entry of its term, cannot apply, or whose own log appends keep failing gives the group
  up after 30 seconds; a stopping leader hands over before it drains
- Any node routes single-key calls to the current group leader, rerouting once, also from a node outside the group;
  without a leader the call fails with `Unavailable` and nothing is written, so a retry with the same `operation_id`
  is safe
- Forwards detect a dead peer: HTTP/2 keepalive pings on forward connections and a bounded dial
  (`ForwardConnectTimeout`, default and maximum 500 ms) report a down owner as `owner_unreachable` instead of a timeout
- On RF>1, followers apply committed entries and compact their group logs, and expiry is decided by the leader through
  committed records
- Replica groups repair their members with no operator action: a lagging follower catches up from the leader's log; a
  follower behind the compacted log, or one back on an empty data directory, gets a state transfer of the group's data
  once enough members confirm their term; the leader's group log is compacted past a follower that is down once it
  reaches 1 GiB
- A new replica group starts only once every member is up; a member on an empty data directory holds an unseeded copy
  that grants no vote and takes no entries until it is repaired
- Journal group commit is configurable as `Squirix:Cluster:Journal` (`GroupCommitMaxWait`, `GroupCommitMaxBatch`) and
  backpressure as `Squirix:Cluster:Backpressure`, including per-client and rate limits (`SquirixServerJournalOptions`,
  `SquirixServerBackpressureOptions`)
- Client: every cache operation runs under one 15 s deadline that is sent to the server and shared by retries,
  endpoint failover and owner routing; idle connections are pinged, so a silent node is dropped and redialed
- `GetOrAddAsync`: a canceled caller that shares a factory run with other callers on the same key stops waiting without
  canceling them, and the factory's token is canceled only when every waiting caller has canceled; a caller that arrives
  after the shared request was sent sends its own request with the produced value, so its result is never older than
  its call
- Readiness: `Degraded` while a journal write or flush is stalled for 5 s or snapshots keep failing, `Unhealthy` while
  the journal pipeline is latched as failed; nodes configured with different RF=1 rings refuse cache calls and fail
  `ring_agreement`
- `/health/ready/details` lists replica groups and, on a leader, each other copy with its state and lag; new metrics
  for roles, terms, lag, quorum availability, leader authority, catch-up, state transfers, group log compaction,
  unknown commits, idempotency capacity and memory rejections by reason (`replica_pressure` among them)
- A group refuses memory-growing writes while one of its members reports critical memory pressure
- Idempotency: replicated hosts deduplicate in the replica group (replayable for at least one minute, up to 15
  minutes); RF=1 nodes bound the replay store by bytes (`SQUIRIX_IDEMPOTENCY_MAX_BYTES`)
- `squirix-server doctor` checks the default data directory too, reports unseeded replica copies, and fails on a
  replica state mismatch; refused internode certificates are logged with the reason and remote endpoint
- Journal crash safety: a mutation is applied to memory only after its frame is durable; a failed fsync or flush
  latches the pipeline and reports `COMMIT_OUTCOME_UNKNOWN`; startup cuts only a provable torn tail and otherwise fails
  naming the segment; appends that cannot fit are refused before they enter the ring; manifest, snapshot and
  compaction publishes are crash-atomic and never overwrite an existing file
- Durable directory entries: on Unix new journal segments, durable files and directories flush their directory entry;
  Windows relies on NTFS metadata journaling, flushes data with `FlushFileBuffers` and no longer opens files
  write-through
- Snapshots: no 2 GiB cap; a failed snapshot is retried with backoff instead of stopping the host; snapshots keep
  running at critical memory pressure; a node whose data exceeds `JournalMaxTotalBytesMb` keeps accepting writes after
  its first snapshot
- Replication correctness: committed-tail recovery at start, ordered appends per follower, term checks for a deposed
  leader, a stale group log append reported as outcome unknown and latched, votes durable in both metadata slots, and a
  write without a majority refused as `Unavailable`
- Idempotency: retries keep their outcome across restarts, snapshot cuts and memory pressure; fingerprints are
  length-prefixed and cover the requested expiration; an id reused for another request is a mismatch
- Clocks: expiry, idempotency ageing, deadlines, snapshot and retention intervals run on the server clock or monotonic
  time
- Routing: the entry node forwards the original RPC unchanged to the owner, forwarded calls are admitted only to a free
  slot and no longer wait for a per-peer permit, and the leader waits of one call share one attempt budget
- Security: internal-only endpoints are selected by the connection (internal port and client certificate), not the
  `Host` header, which a public caller could forge; journal spans no longer carry raw cache keys; malformed wire times
  and lengths are refused instead of throwing
- Memory accounting counts every entry where it enters and leaves memory, including follower copies and recovered
  entries, and no longer restarts from zero
- Shutdown and disposal: deterministic host stop order, bounded pool and worker shutdown, and dispose paths that never
  throw or hang on a stuck flush
- A node whose URI is a loopback IP literal listens on exactly that address
- Key ownership hashing with XxHash64, reused across the layers of one request
- Lock-free local cache reads (10–30× faster under contention), `CacheKey` as a value type, and allocation-free value
  reads, replicated ones included
- Expiry sweep reads due keys from a deadline index, and expiry tombstones commit in batches of up to 64 under one
  majority
- RF=1 idempotent mutation rate at a full replay store raised from about 1,090 to about 8,700 per second
- Metrics recorded without a global lock or a label string per call; one inbound gRPC interceptor; control paths
  without exceptions
- Faster leader promotion (about 2.3 s to 0.33 s with a silent old leader), group metadata written in place, cached
  peer certificate chain validation, and buffered durable files on Windows (group log append 15–25% faster)

dotnet add package squirix --version 0.1.0-preview.9
dotnet add package squirix.server --version 0.1.0-preview.9
dotnet tool install --global squirix.server.tool --version 0.1.0-preview.9
