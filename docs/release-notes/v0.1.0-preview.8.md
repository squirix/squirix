# v0.1.0-preview.8

## Summary

Squirix 0.1.0-preview.8 introduces replica sets with synchronous replicated mutations and majority-based
leader election, so RF>=3 clusters survive single-node loss on the remaining majority. RF=1 keeps single-owner
behavior with durability per node, and RF>1 requires explicit opt-in plus persistence and inter-node mTLS.

Still an early preview — not production-ready. API, wire format, and on-disk layouts may change during 0.x.

## Changes

- Synchronous replicated mutations with majority commit; RF=1 keeps single-owner behavior with no replication or automatic failover
- Explicit replication opt-in for RF>1 (`ReplicationEnabled`, `--enable-replication`); RF>1 startup without it is refused
- Majority leader election with durable `current_term` and log-freshness voting
- Leader authority and fencing with bounded client rerouting on stale terms
- Failover, partition-safety, and rejoin proofs for RF>=3; RF=2 stays a synchronous mirror with no promotion after peer loss
- Write-ahead idempotency intent recorded before mutation execution
- Replication metrics and replica readiness on `/metrics` and `/health/ready/details`
- `squirix-server doctor` reports replica status for RF>1 hosts
- RF=3 Docker Compose HA example with persistence and mTLS
- Homogeneous cluster package version enforced through the topology fingerprint; mixed versions fail readiness

## Install

dotnet add package squirix --version 0.1.0-preview.8
dotnet add package squirix.server --version 0.1.0-preview.8
dotnet tool install --global squirix.server.tool --version 0.1.0-preview.8
